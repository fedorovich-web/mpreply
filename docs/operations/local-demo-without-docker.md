# Локальный демо-кабинет без Docker

Демо использует обычный FastAPI, миграции Alembic, PostgreSQL и тот же кабинет Next.js. Подмена API или отдельный демонстрационный фронтенд не используются.

## Запуск на Windows

Бинарники PostgreSQL 18.1 получены из ZIP-архива EnterpriseDB, на который ссылается официальная [страница PostgreSQL для Windows](https://www.postgresql.org/download/windows/). Они распакованы в `%LOCALAPPDATA%\MPReply\local-runtime\postgresql-18.1\pgsql`. Служба Windows не устанавливается.

Из корня репозитория:

```powershell
.\apps\api\.venv\Scripts\python.exe .\scripts\start-local-demo-api.py
```

Оставьте терминал API открытым. Запустите фронтенд в другом терминале из `apps/web` командой `npm run dev`, затем откройте `http://localhost:3000/demo`. API работает в процессе команды, чтобы Windows не завершал его при выходе отдельного запускающего процесса.

Скрипт использует отдельную базу `mpreply_demo` на `127.0.0.1:55432`, генерирует собственные локальные секреты и запускает API на `127.0.0.1:8000`. Пароли не выводятся. При занятом порте API существующий процесс остаётся работать.

В демо доступны четыре примера обращений и один ответ на проверке. Ключи маркетплейсов нерабочие, аккаунты отключены; изменение данных и внешняя отправка запрещены на уровне API. Ключи почтового и ИИ-провайдеров при запуске очищаются в окружении дочернего процесса.

Этот запуск проверяет кабинет и чтение данных. Redis, воркер, планировщик, отправка писем, ИИ и реальные действия маркетплейсов в него не входят. `/health/ready` без Redis возвращает 503; это не полная проверка готовности стека к развёртыванию.

Отдельная проверка фоновой подготовки ИИ-черновиков использует изолированную тестовую базу и подмену внешних HTTP-запросов, сохраняя настоящий PostgreSQL и сервисы приложения:

```powershell
.\apps\api\.venv\Scripts\python.exe .\scripts\check-local-automatic-drafts.py --check-migration
```

Эта команда не запускает непрерывный воркер и не подтверждает доставку через Redis. Результат относится только к конкретному локальному запуску с подменёнными внешними запросами.

## Проверка настоящего API в браузере

Из `apps/web`:

```powershell
$env:MPREPLY_REAL_API_TEST = "1"
npx playwright test e2e/demo-api-runtime.spec.ts --project=chromium
Remove-Item Env:\MPREPLY_REAL_API_TEST
```

Тест проверяет русский и английский кабинеты без перехвата API-запросов, загрузку данных из PostgreSQL и HTTP 403 при попытке изменения данных или добавления ключей.

## Остановка

API останавливается через Ctrl+C в его терминале. PID сохранён в `%LOCALAPPDATA%\MPReply\local-runtime\api-demo.pid`. PostgreSQL останавливается штатно:

```powershell
& "$env:LOCALAPPDATA\MPReply\local-runtime\postgresql-18.1\pgsql\bin\pg_ctl.exe" -D "$env:LOCALAPPDATA\MPReply\local-runtime\demo-data-20260930" -w stop
```

Данные и локальная конфигурация остаются в отдельном каталоге runtime.
