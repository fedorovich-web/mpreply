# Lava.top и Яндекс ID — настройка MPReply

Код интеграций подготовлен в `feat/auth-email-resend`. До выкладки и проверки конфигурации обе возможности выключены. Проверки с HTTP-заглушками и отдельной локальной PostgreSQL не подтверждают работу реального кабинета провайдера.

## Переменные в Dokploy

Добавлять в **MPReply → Environment** приложения с production Compose. Ключи остаются на сервере API, worker и scheduler. Не добавлять их в отдельный Redis, в `NEXT_PUBLIC_*`, репозиторий или переписку.

```dotenv
LAVA_ENABLED=false
LAVA_API_KEY=
LAVA_PRODUCT_ID=
LAVA_OFFER_ID=
LAVA_WEBHOOK_SECRET=
YANDEX_OAUTH_ENABLED=false
YANDEX_OAUTH_CLIENT_ID=
YANDEX_OAUTH_CLIENT_SECRET=
```

Значения вводятся после `=`, без кавычек и пробелов вокруг него. Строки с пустым значением — шаблон для заполнения, а не рабочая конфигурация. Существующие `AUTH_SECRET_KEY`, `CREDENTIALS_ENCRYPTION_KEY`, адреса БД/Redis и ключи других провайдеров сохраняются. Для Яндекса используется существующий Fernet-ключ `CREDENTIALS_ENCRYPTION_KEY`; менять его при настройке нельзя, поскольку им зашифрованы и другие сохранённые данные.

`API_BASE_URL=https://api.mpreply.ru`, `WEB_APP_URL=https://app.mpreply.ru`, защищённые auth-cookie и точный CORS уже входят в production-контракт. Внешние токены Яндекса не сохраняются; короткоживущий PKCE verifier шифруется и удаляется после использования.

## Lava.top

1. Создать API-ключ в Lava.top и сохранить его непосредственно в `LAVA_API_KEY`.
2. У продукта MPReply включить «Цена по запросу через API». UUID продукта MPReply: `597f1d39-3eec-4f0d-8903-b79648d68643`; сохранить его в `LAVA_PRODUCT_ID`. Для `LAVA_OFFER_ID` открыть [Swagger Lava](https://gate.lava.top/docs), нажать Authorize и внести `LAVA_API_KEY`, затем Products → GET `/api/v2/products` → Try it out → Execute. В `items` найти `data.id` продукта MPReply и скопировать `data.offers[].id` его разового предложения. Если предложений несколько, сверить их названия и разовый тип, а не выбирать первый без проверки. Эти два UUID различаются.
3. Создать отдельный случайный webhook-секрет из 32–80 ASCII-символов без пробелов. Он должен отличаться от API-ключа. Сохранить одинаковое значение в `LAVA_WEBHOOK_SECRET` и заголовке авторизации webhook в Lava.top.
4. В форме webhook указать URL `https://api.mpreply.ru/api/billing/lava/webhook`, события `payment.success` и `payment.failed`. Выбрать «API key вашего сервиса» и вставить webhook-секрет в поле API key. Lava передаёт его заголовком `X-Api-Key`; Basic обработчиком MPReply не используется.
5. После выкладки и проверки заполненных значений поставить `LAVA_ENABLED=true`, сохранить Environment и выполнить обычный Deploy MPReply.

Секрет webhook можно создать в Windows PowerShell одной строкой: `([guid]::NewGuid().ToString('N') + [guid]::NewGuid().ToString('N')) | Set-Clipboard`. Команда копирует 64 символа в буфер обмена; вставить одно и то же значение в оба поля. В Linux-терминале сервера: `openssl rand -hex 32`, затем скопировать напечатанную строку. Строка из одних нулей не подходит.

Все покупки отправляются с `periodicity=ONE_TIME`, в RUB. Нет привязки карты или автопродления. Цену, количество ответов и период определяет API MPReply; браузер передаёт только состав покупки. Год оплачивается целиком, ответы начисляются ежемесячно. Новый тариф встаёт после текущего оплаченного периода; накопленные оплаченные ответы сохраняются, для расходования нужен действующий оплаченный тариф.

Завершение страницы оплаты не подтверждает покупку. Только аутентифицированное уведомление и проверенный GET invoice с совпадающими суммой, валютой, идентификатором и продуктом дают начисление. Повтор того же заказа не делает новый POST в Lava. Неопределённый ответ переводится на проверку; автоматическое создание второго счёта запрещено.

Неподдерживаемые возвраты/chargeback сохраняются для ручного разбора без автоматического изменения денег или ответов. Полный процесс возвратов и интерфейс администрирования финансовых исключений в этот запуск не входят.

Для реального приёмочного теста отдельно согласовать одну оплату: проверить ссылку Lava, webhook 204, состояние `paid`, одну запись начисления и отсутствие повторного начисления при повторной доставке. До такой проверки реальная оплата не считается сертифицированной.

## Яндекс ID

1. Платформа «Веб-сервисы».
2. Redirect URI: `https://api.mpreply.ru/api/auth/yandex/callback`. Suggest Hostname оставить пустым: интеграция использует серверный Authorization Code, без Suggest-виджета.
3. Права: «Доступ к адресу электронной почты» и «Доступ к логину, имени и фамилии, полу» (`login:email`, `login:info`). MPReply использует ID, основной email и имя; остальные поля не сохраняет. Дата рождения, фото и телефон не нужны.
4. Внести Client ID и Client Secret напрямую в Dokploy. После выкладки поставить `YANDEX_OAUTH_ENABLED=true`, сохранить и выполнить обычный Deploy.

Проверить новый вход, отмену авторизации, повторный callback, переход в интеграции после регистрации и явное связывание из «Аккаунт». Существующий email не связывается автоматически: сначала вход в MPReply, затем «Связать Яндекс». Для аккаунта, созданного через Яндекс, пароль можно установить через подтверждённое восстановление по email. Повторный вход не создаёт ещё один аккаунт и не выдаёт новый пробный пакет.

## Отключение и диагностика

Поставить соответствующий флаг в `false` и выполнить обычный Deploy. Существующие оплаченные периоды и начисления продолжают обслуживаться; отключение приёма новых платежей не удаляет права уже оплативших пользователей. При выключенном Lava webhook возвращает 503, поэтому его надо снова включить для обработки оставшихся уведомлений. Данные не удалять, Fresh Volumes не использовать.

При ошибке проверять безопасные коды заказа/inbox и состояние контейнеров, не выводить API-ключи, OAuth code/token, cookie или полный Environment в логи. Отдельный тестовый PostgreSQL разрешён только на `localhost`/`127.0.0.1` с именем `mpreply_credit_test_*`; `scripts/check-local-billing.py` не запускает Docker и не подключается к production.

Официальные контракты: [Lava.top API](https://developers.lava.top/ru), [Яндекс ID](https://yandex.ru/dev/id/doc/ru/).
