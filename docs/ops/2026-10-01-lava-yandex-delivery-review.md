# Lava.top, Яндекс ID и исправления PageSpeed — пакет к выкладке

База: `feat/auth-email-resend`, `417add5257b9f5d896ba6d4aca88b39a0d743a19`. Изменения находятся в рабочем дереве; коммит, push, merge и production Deploy этого пакета ещё не выполнялись. Пользователь сообщил о добавлении ключей непосредственно в Dokploy Environment; реальные значения не читались и не проверялись.

## Поведение

- Lava: ручная оплата тарифа/пакетов в RUB, `ONE_TIME`, без автосписаний. Сервер определяет цену. Длительность покупки и начисления сохраняются неизменно. Год оплачивается целиком, ответы выдаются ежемесячно. Продление начинается после доказанного действующего оплаченного периода.
- Один ключ заказа не создаёт повторный счёт. Неопределённый результат POST требует проверки; повторная доставка уведомления не выдаёт второй пакет. Начисление требует аутентифицированного события и проверки конечного состояния invoice, суммы, валюты и связи с заказом.
- Яндекс: Code + PKCE, одноразовый state, привязка к браузеру, email/info. Вход создаёт новый аккаунт либо использует уже связанную идентичность. Совпадение email не связывает существующий аккаунт автоматически; связь выполняется после входа в MPReply. Код и токен не попадают в access log.
- CSP: случайный nonce на каждый запрос, `strict-dynamic`, без `unsafe-eval` в production. HSTS на год, COOP `same-origin`, XFO `DENY`, `nosniff`, Referrer-Policy. CSP блокирует вставленный посторонний скрипт; штатные inline-скрипты и JSON-LD получают nonce.
- CSS кабинета подключается только в RU/EN ветках кабинета. Исходные утверждённые изображения сохранены; главная получает responsive-версии, hero/CTA используют импорты с версией по содержимому.
- Нативные библиотеки Sharp включены в standalone tracing: отсутствие DLL приводило к незаметной отдаче оригинала вместо уменьшенного файла. Проверяется формат и объём фактического HTTP-ответа, а не только наличие `srcset`.

## Измерения и оставшиеся ограничения

Публичный отчёт пользователя от 1 октября показывает mobile 99/100 и остальные категории 100. Это другая среда и версия Lighthouse; локальные оценки не доказывают изменение production PageSpeed. Повторная проверка опубликованного сайта нужна после Deploy.

Фактический hero при ширине 750: 69 912 bytes WebP против 133 469 bytes исходного AVIF, 750 px против 1481 px. В локальном Lighthouse responsive-image audit теперь проходит. Предупреждение об unused CSS сократилось примерно с 43 до 28 KiB; примерно 29 KiB unused JS и 13 KiB legacy JS остаются в общем runtime-пакете Next.js/React. Это не подтверждение, что всю эту часть можно безопасно удалить: Lighthouse измеряет исполнение при первой загрузке.

Trusted Types пока не включены. Диагностический запуск с `require-trusted-types-for 'script'` блокирует `HTMLScriptElement.src` загрузчика Turbopack при переходе на /features, после чего Next пытается полную навигацию. Разрешающий любые строки default policy не добавлялся. Этот пункт безопасности остаётся открытым и требует совместимого загрузчика.

Независимый обзор интеграций выявил пять Important замечаний; все исправлены одним проходом с RED → GREEN регрессиями: начисления без scheduler, очистка OAuth query в access log, refresh сессии при связывании, освобождение ключа только для доказанно несозданного заказа и сохранение доказанного legacy paid периода. Новые исправления PageSpeed проверены дополнительно локально.

Docker не запускался. Контейнерный runtime, реальные платежи Lava и вход в реальный Яндекс не сертифицированы. Возвраты/chargeback сохраняются для ручного разбора; автоматический финансовый процесс возврата не входит в этот пакет.

## Следующий разрешаемый шаг

Один коммит подготовленного пакета, обычный push в существующий PR №13 и технический Deploy этого коммита в существующий MPReply Dokploy. Main не объединяется. После проверки конфигурации включить Lava/Яндекс и проверить миграции, HTTPS, health и доступность новых маршрутов. Реальную оплату проводить только по отдельному явному разрешению.
